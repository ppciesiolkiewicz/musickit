# Videos

Videos a note or an exercise plays: the app's library of practice videos, and the videos a teacher records in the notes creator.

| File | What |
| --- | --- |
| `library.ts` | `VIDEO_LIBRARY`: the practice videos rendered from `videos/<id>.json` (`npm run video`), with title, line, area, length and the formats uploaded (`published`). Files are `VIDEO_BASE/<id>-<format>.mp4`; `VIDEO_BASE` is `NEXT_PUBLIC_VIDEO_BASE` or `/videos` (`public/videos/`, git-ignored). A video with nothing published is offered nowhere. Pure. |
| `ref.ts` | `VideoRef`: `{ source: "library", id }`, `{ source: "recording", id, title }` or `{ source: "placeholder", text? }`, and `sanitiseVideoRef`. Pure. |
| `Placeholder.tsx` | A placeholder: **Video coming soon** for a reader (with the placeholder's `text` under it, when it has one), **Record this video** (a button the host wires to its recorder) in the creator. |
| `recording.ts` | The recorder's pure parts: the recorded type, file names, a take's default name, the ten-minute limit, and `videoPath(userId, id, type)` (where the file goes in the Blob store; the server checks the same). |
| `queue.ts` | The upload queue's pure parts: `SavedVideo`, `QueuedVideo` (a take with its `accountId`, `state` `waiting`/`uploading`/`failed`, `tries`, the server's `error`, and `fileUp` once the file is in the store and only the row is missing), `nextToUpload` (the oldest not uploading), `afterFailure`, `afterSuccess`. |
| `store.ts` | IndexedDB `musickit-videos`, two kinds of entry. Without accounts and for a visitor, the local library: `saveVideo`, `listVideos`, `getVideo`, `renameVideo`, `deleteVideo` (nothing uploaded). Signed in, the upload queue (entries with a `state`): `enqueue`, `listQueued(accountId)`, `markQueued`, `dropQueued`; a take the browser refused to store is kept in the page's memory (`keepUnstored`). |
| `serverVideos.ts` | The API from the browser: `listServerVideos`, `renameServerVideo`, `deleteServerVideo`, `videoFileUrl(id)` and `uploadQueued(v)`: the file with `upload()` from `@vercel/blob/client` (private, to `videoPath`), then `POST /api/videos`. A take whose file is up (`fileUp`) only retries the row; an upload error tries the row once (the file may be up from an earlier page); a 409 for an id in the player's own list counts as saved. Every request but the list sends `X-Account-Id` (`accountHeaders`, `userData/client/accountHeader.ts`); a 409 `account-changed` on the row is refused with the reload line, never taken for an id already in the list. |
| `uploads.ts` | The queue's runner, one per page: uploads the account's queued takes one at a time, each at most once per run; the local copy is dropped only once `POST /api/videos` succeeds. `resumeUploads`/`useResumeUploads` (mounted by `UserDataProvider`) run it on every signed-in page load, a take left `uploading` by a closed page waiting again. While a take is uploading or waiting (or failed and only in memory) it reports "saving" to the userData registry, so the leave warning covers it; a failed upload is shown in **My videos**, not in the save notice. `useVideoLibrary()`: the queued takes first, then the uploaded ones (signed in), or the local library; `retry`, `download`, `rename`, `remove`. |
| `VideoPlayer.tsx` | Plays a ref with the browser's controls: a recording in this browser from its blob, else (signed in, or a visitor reading a shared note) from `videoFileUrl`; without accounts a recording not in this browser says so. A file that won't play is asked again with a one-byte range: a 404 is "This video is gone" (deleted, or not shared with this viewer), anything else the connection notice; a placeholder reads Video coming soon. |
| `VideoRecorder.tsx` | Camera and microphone: **Start camera**, **Record** / **Stop** (a clock, ten minutes at most), then the take to watch, a **Name**, **Save and add to …**, **Record again**, **Download**. Signed in, saving queues the take and starts the upload; if the browser won't store it, the recorder warns that the take is lost should the upload fail, and the button becomes **Upload and add to …**. |
| `VideoChooser.tsx` | The Add a video dialog's body, its tabs in this order: **My videos** (watch, add, download, delete; a take not uploaded yet says so, a failed one has **Try again**), **Record**, **Placeholder** and **attunr video library**. |
| `server/rules.ts` | Server only, pure. `MAX_VIDEO_BYTES` (1 GB), `VIDEO_TYPES` (WebM or MP4), `isVideoId` (a lower-case UUID), `videoPath(userId, id, type)` (`videos/<userId>/<id>.<webm|mp4>` in the private Blob store), `ownsPath`, `checkUpload({ id, type, size })` and `isPrivateBlobUrl` (only `https://<store>.private.blob.vercel-storage.com/...`). |
| `server/access.ts` | Server only. Who may do what, over `UserDataRepo` (`@/features/userData/server/repo`): `planUpload` (before the upload token), `completeUpload` (after the upload: own path, the file found by `head`, its URL private, then the row; a public blob is deleted and refused, since the browser chooses the access and the upload token doesn't bind it; a taken id is 409), `listMine`, `renameMine`, `deleteMine`, and `watch` (`canWatch`: the owner, a live note share, or a plan invite the viewer claimed; see `userData/server/shares.ts`). Tested over the memory repo. |
| `server/stream.ts` | Server only, pure. `blobRangeHeaders` (one byte range passed to Blob's `get`), `streamAnswer(read, cache?)` (200, or 206 when Blob sent `content-range`, with `content-range`, `content-length`, `accept-ranges`, `content-type` and `cache-control` as `cache` says, `private, no-store` by default; an error is always `no-store`; the content-video file route passes `public, max-age=3600`), `failedStream` (416 or 502). |

Routes (in `src/app/api/videos`): `upload` (POST, the client-upload token for `upload()` from `@vercel/blob/client`, `clientPayload` `{ id, type, size }`; 503 without a Blob token), `/` (GET the player's list, POST `{ id, title, type, seconds, width, height, path }` once the upload finished), `[id]` (PATCH `{ title }`, DELETE the row and then the file) and `[id]/file` (GET the file with Range, checked by `watch` on every request; 404 for anyone who may not watch it, and on a site without a database or a store). The browser picks the id (`crypto.randomUUID()`) and the server keeps it, so a note's `VideoRef` doesn't change. The Blob token is `blobToken` in `@/lib/blob`. Still to check against the real store: that a ranged `get` answers 206 with `content-range`, that `head` gives the size and the URL, and the store's access mode (whether it refuses public writes by itself, and that `head` of a public upload has a `.public.` host).

Used by: the stage's `video` widget (`StageWidget`, notes and the studio), the studio's Add a video dialog (`StudioApp`, from the palette's **Video** and **Record a video**), and the plan's `video` tool (`exercises/basics/video`, picked by the AI from the published library).

## Adding a library video
1. Write `videos/<id>.json` and render it horizontal: the library is 16:9 only (`npm run video -- videos/<id>.json --only 16x9`, see `spec/video.md`).
2. Upload `out/videos/<id>-<format>.mp4` to the video host (`NEXT_PUBLIC_VIDEO_BASE`); for local work copy it to `public/videos/`.
3. Add the entry to `VIDEO_LIBRARY` with `published: ["16x9"]` (a test holds the library to horizontal). Its `title` and `about` are teaching text (`teaching-voice`). The test checks the id, the length and the formats against the config.
