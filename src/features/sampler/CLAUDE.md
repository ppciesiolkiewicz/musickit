# Sampler: rules

Instruments built from samples that are uploaded or generated by a provider. Behaviour spec: `spec/sampler.md`.

- Imports only `@/features/sound` and shared components. Never the looper, creator or guitar tools. The sound feature knows nothing about the sampler: it only offers a runtime instrument registry (`engine/runtime.ts`).
- Keys never reach the browser. The app's provider key (`ELEVENLABS_API_KEY`) is read only in `src/app/api/sampler/generate/route.ts`, and only used when `SAMPLER_ACCESS_CODE` is also set and sent. A person's own key travels in the `x-provider-key` header, is forwarded and never stored or logged by the server.
- Never forward a provider's error body to the client (`server/elevenlabs.ts` maps statuses to fixed messages).
- Project structure and audio persist through `SamplerStore` (`store/types.ts`). IndexedDB today; a cloud store means a new implementation of the same interface.
- New provider: add it to `PROVIDERS`, a `server/<name>.ts` with an injectable `fetch`, a case in the route, a test.
- Model code (`model/`) is pure and tested. Run the tests and the type check before every push.
