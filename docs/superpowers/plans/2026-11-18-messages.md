# Messages Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development (recommended) or executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Signed-in users send us messages (with the page they were on) from a chat bubble and a Send feedback page; we read, reply and close threads at `/dev/messages`; contact form messages land there too.

**Architecture:** A new feature `src/features/messages` with a pure model (validation, context, unread), a repo interface with memory and drizzle versions (same pattern as `src/features/userData/server/repo*.ts`), and service functions tested over the memory repo. Thin route handlers on top: `/api/me/messages` for the user (`signedIn()`), `/api/dev/messages` for us (`devGate()`). Client: a bubble mounted in the root layout, polling; a `/feedback` page; a `/dev/messages` page.

**Tech Stack:** Next.js (read `node_modules/next/dist/docs/` before writing routes/pages — this Next differs from training data), drizzle + Postgres, `node:test` via tsx, Tailwind, Resend through `sendMail`.

**Spec:** `docs/superpowers/specs/2026-11-17-messages-design.md`

## Global Constraints

- Only signed-in users see the bubble and may call `/api/me/messages`; everyone else gets 401 (via `signedIn()`), and visitors see no bubble.
- Message body: trimmed, non-empty, at most 4000 characters (`MAX_MESSAGE` from `src/features/contact/contact.ts`).
- Context `selection` at most 500 characters; every context field optional.
- Several threads per user. Send feedback page and a signed-in contact form message always start a new thread; a bubble message goes into the thread open in the panel, or starts one.
- Writing in a closed thread reopens it. The user never sees "closed".
- Email to us at most once per thread per 10 minutes; contact-route inserts send no extra email. No Resend key → message still stored, no error.
- Polling: panel every 20 s while open; unread count on load and every 60 s while `document.visibilityState === "visible"`.
- Every client fetch goes through `send()` (`src/features/account/ui/parts.tsx`, has a timeout) and shows an error inline on failure; typed text stays until a send succeeds.
- Everything under `/dev/messages` and `/api/dev/messages` 404s in production (`devOnly()` / `devGate()`).
- Interface strings: load `design:ux-copy` and "Words about the app" in `teaching-voice` before writing any; plain, short, no exclamation marks; report every string old → new.
- Don't `git add` in the main checkout's shared index: commit with a temp `GIT_INDEX_FILE` (read-tree HEAD, add your paths, commit), then `git reset -q HEAD -- <paths>`.
- Before `db:migrate`, check where `DATABASE_URL` in `.env.local` points; migrate the local docker DB only, never production without asking.

## Review Focus

1. A user asks for (or posts into) another user's thread id → 404, never their messages. Test in Task 3.
2. A bubble message into a thread we closed → appended and the thread reopens, shows as open in `/dev/messages`. Test in Task 3.
3. Junk context from the client (non-strings, a 10 000-char selection, a `path` that is a full URL to another site) → stored trimmed/dropped, never rejected the message. Test in Task 1.
4. Two messages a minute apart → one email to us, not two; one 11 minutes later → a second email. Test in Task 3.
5. Contact form with neither Resend nor blob configured but a DB → succeeds and is stored (today it 503s). Test in Task 5.

### Task 2: Schema and repo

**Files:**
- Modify: `src/lib/db/schema.ts` (two tables after `planReviews`)
- Create: `drizzle/0025_*.sql` (generated) and its `drizzle/meta` files
- Create: `src/features/messages/server/repo.ts`, `repo.memory.ts`, `repo.drizzle.ts`
- Test: `src/features/messages/server/repo.memory.test.ts`

**Schema** (spec's, with two denormalised times so unread needs no join):

```
message_threads: id uuid pk defaultRandom; kind text not null default 'support'; user_id uuid null → users.id cascade;
  email text null; status text not null default 'open' (check in ('open','closed')); last_at, last_user_at, last_admin_at,
  user_read_at, admin_read_at, emailed_at timestamptz (last_at not null, others null); created_at not null defaultNow;
  index (user_id, last_at), index (status, last_at)
messages: id uuid pk defaultRandom; thread_id uuid not null → message_threads.id cascade; from_admin boolean not null;
  body text not null; context jsonb null; at timestamptz not null; index (thread_id, at)
```

**Interfaces:**
- Produces (`repo.ts`):
  - `type ThreadRow = { id: string; kind: "support"; userId: string | null; email: string | null; status: "open" | "closed"; lastAt: Date; lastUserAt: Date | null; lastAdminAt: Date | null; userReadAt: Date | null; adminReadAt: Date | null; emailedAt: Date | null; createdAt: Date }`
  - `type MessageRow = { id: string; threadId: string; fromAdmin: boolean; body: string; context: MessageContext | null; at: Date }`
  - `interface MessagesRepo { createThread(t: { userId: string | null; email: string | null; at: Date }): Promise<ThreadRow>; thread(id: string): Promise<ThreadRow | null>; threadsOf(userId: string): Promise<ThreadRow[]> /* newest lastAt first */; allThreads(filter: { status?: "open" | "closed"; limit: number }): Promise<(ThreadRow & { userEmail: string | null; userName: string | null; preview: string })[]>; addMessage(m: Omit<MessageRow, "id">): Promise<MessageRow> /* also bumps lastAt and lastUserAt/lastAdminAt */; messagesOf(threadId: string): Promise<MessageRow[]> /* oldest first */; updateThread(id: string, patch: Partial<Pick<ThreadRow, "status" | "userReadAt" | "adminReadAt" | "emailedAt">>): Promise<void>; lastMessage(threadId: string): Promise<MessageRow | null> }`
  - `memoryMessagesRepo(users?: Map<string, { email: string; name: string }>): MessagesRepo`, `drizzleMessagesRepo(db): MessagesRepo`
  - `messagesStore(env = process.env): { repo: MessagesRepo } | null` in `server/store.ts` (like `userData()`)

**Interfaces:**

  - The route's mailer is `(m) => sendMail(m, process.env)` from `src/features/account/server/mail.ts` (widen `sendMail`'s param type to the `Mailer` mail shape if needed).
