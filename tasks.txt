======================== How TaskSeries work ========================
A TaskSeries is a named group of tasks that belong together: one feature or one kind of work, picked up one at a time.
- Header line: `TaskSeries <Name>:`. Every task under it is `<Name><n>:`, numbered from 1 in the order they were added
  (CounterTask1, CounterTask2; NEW1 ... NEW16). A new task takes the next free number; numbers are never reused, so a
  commit message or a session report can name one ("NEW13", "MissingTools4") and it stays findable.
- First line of a task: what it is, with `[NEW <date>]` when an agent added it. Under it: what was decided, what is
  open, where the design doc and plan are.
- Progress goes under the task as dated notes, newest last: `[<date> done] what was built, where`, then what is left.
  A task finished for good gets `[DONE <date>]` on its first line and moves to tasks-done.txt (top).
- Order inside a series is the order to work in unless a task says it waits for another ("after NEW8").
- A series can point into another: a task that needs a missing tool names the MissingTools task instead of repeating it.
